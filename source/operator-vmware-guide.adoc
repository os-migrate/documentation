=== Multi-Connection Tuning for NBD Transfer

When using a custom nbdkit plugin, you can enable multi-connection parameters to improve disk transfer performance. This feature allows nbdkit to establish multiple parallel connections to the source VMware datastore and nbdcopy to use multiple concurrent requests.

==== Configuration Parameters

Two new optional parameters control multi-connection behavior:

[cols="2,3,2",options="header"]
|===
| Parameter | Description | Example Values

| `nbdkit_options`
| Dictionary of extra parameters appended to the nbdkit server command as `key=value` tokens. Only applied when `custom_nbdkit_plugin` is set.
| `multiconn: true`, `sessions: 8`, `pipeline: 16`

| `nbdcopy_options`
| Dictionary of extra flags appended to the nbdcopy command as `--key=value` tokens.
| `connections: 16`, `requests: 64`
|===

[IMPORTANT]
====
* `nbdkit_options` are *only honored* when `custom_nbdkit_plugin` is configured. With the built-in vddk plugin, these options are ignored.
* When `nbdkit_options` are set with a custom plugin, the migration module waits 10 seconds for the backend connection to establish before starting nbdcopy.
* Both parameter dictionaries are rendered in sorted key order for deterministic command generation.
====

==== Example Usage

[source,yaml]
----
- name: Migrate VM with multi-connection tuning
  os_migrate.vmware_migration_kit.migrate:
    dst_cloud: "{{ my_dst_cloud_auth_details }}"
    user: "{{ my_vcenter_username }}"
    password: "{{ my_vcenter_password }}"
    server: "{{ my_vcenter_hostname }}"
    vmname: "{{ target_vm_name }}"
    osmdatadir: "{{ os_migrate_data_directory_path }}"
    vddkpath: "{{ global_vddk_path }}"
    # Custom plugin is required for nbdkit_options to take effect
    custom_nbdkit_plugin: "/usr/lib64/nbdkit/plugins/nbdkit-custom-plugin.so"
    nbdkit_options:
      multiconn: true
      sessions: 8
      pipeline: 16
    nbdcopy_options:
      connections: 16
      requests: 64
  register: migrate_vm_output
----

==== Performance Considerations

* **sessions**: Controls the number of parallel NBD connections nbdkit opens to the source datastore. Higher values (e.g., 8-16) can improve throughput for large disks.
* **pipeline**: Enables request pipelining within each session. Values like 16 allow multiple in-flight requests per connection.
* **connections**: Sets how many parallel connections nbdcopy uses to read from nbdkit. Should typically match or exceed the nbdkit sessions value.
* **requests**: Controls the maximum number of concurrent in-flight requests in nbdcopy. Higher values (e.g., 64) can saturate available bandwidth.

Test different combinations based on your network capacity and datastore performance. Start with conservative values and increase gradually while monitoring transfer speeds.
